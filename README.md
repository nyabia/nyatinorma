# nyatinorma

pi의 모델 provider와 TUI로 실행하는 로컬 computer-use 에이전트입니다. Bun, Tauri, 별도 모델 서버는 필요하지 않습니다.

기본 프리셋은 없습니다. 자연어로 작업을 요청하면 모델이 관측하며 진행하고, 재사용할 절차를 발견하면 스스로 프리셋·지식·후보 세트로 저장합니다. 저장은 새 작업 실행을 뜻하지 않습니다.

현재는 실험적인 소스 배포입니다. Node.js 22.19 이상, npm, 별도로 설치한 `cua-driver`, 이미지 입력을 지원하는 모델 서버가 필요합니다. 설치 프로그램과 자동 업데이트 명령은 아직 제공하지 않습니다.

## 실행

```sh
git clone https://github.com/nyabia/nyatinorma.git
cd nyatinorma
npm ci
cp nyatinorma.example.json nyatinorma.json
# nyatinorma.json에서 실제 모델명과 대상 앱을 설정
npm run doctor
npm start
```

이미 설치했다면 `npm start`만 실행합니다. macOS는 `nyatinorma.command`, Windows는 `nyatinorma.cmd`도 사용할 수 있습니다. 선택 메뉴 없이 바로 입력할 수 있고, 이름 없는 임시 기록이 자동 생성·저장됩니다. `/save 이름`은 현재 기록에 이름을 붙이며 `/runs`에서 임시 기록도 다시 열 수 있습니다. `npm start -- --continue`는 이전 대화를 이어갑니다.

TUI에서 `/play` 또는 자연어로 작업을 지시합니다. `npm start` 자체는 게임 입력을 시작하지 않습니다.

상시 안내는 `자연어로 요청하세요 · /help 도움말` 한 줄입니다. 명령과 이력 탐색 설명은 `/help`에서 확인합니다.

앱 자체 자동진행 기능이 요청에 적합하면 이를 이용할 수 있습니다. `ny_wait`는 모델 호출·반복 캡처 없이 기다렸다가 끝에 한 번 관측합니다. `/stop`과 Escape는 에이전트를 멈추며, 앱 자체 자동진행까지 해제하지는 않습니다.

| 명령 | 동작 |
|---|---|
| `/preset` 또는 `/task` | 프리셋으로 독립된 새 실행 생성 |
| `/save 이름` | 현재 기록에 이름 붙이기; 저장은 이미 자동으로 진행됨 |
| `/runs` | 임시 기록을 포함한 이전 실행 선택·연결 |
| `/chat` | 이전 기록을 보존하고 새 임시 기록으로 대화 |
| `/newtask 목표` | 재사용할 프리셋 생성, 실행은 만들지 않음 |
| `/play [이번 범위]` | 현재 기록에서 지정한 범위 진행 |
| `/new` | 새 대화와 빈 임시 기록 |
| `/tree` / `/fork` | 이전 대화 지점으로 이동 / 별도 대화로 분기 |
| `/resume` | 저장된 대화 재개 |
| `/help` | 기본 사용법과 이력 기능 안내 |
| `/plan` | 단계별 실행 계획과 미확인 항목 확인 |
| `/feedback 교정 내용` | 사람의 피드백을 관측 ID와 저장하고 개선 요청 |
| `/sets` | 현재 작업의 후보 세트 목록 |
| `/trace` | 최근 선택·실행·검증 기록 |
| `/doctor` | Cua 권한·대상 창 확인 |
| `/stop` 또는 Escape | 현재 실행 취소 |

## 모델과 커스텀 서버

모델 선택은 pi 기본 `/model`을 사용합니다. 별도의 “커스텀 추가” 항목 대신, `.nyatinorma/pi/models.json`의 `providers`에 서버를 등록하면 `/model`을 열 때 목록을 다시 읽습니다. pi 설정을 프로젝트 안에 격리하므로 전역 `~/.pi/agent/models.json`을 수정하는 경로와 다릅니다.

SGLang 등 OpenAI 호환 서버 예시(기존 providers 항목은 보존하세요):

```json
{
  "providers": {
    "my-server": {
      "baseUrl": "http://localhost:8000/v1",
      "api": "openai-completions",
      "apiKey": "local",
      "models": [{
        "id": "your-vision-model",
        "reasoning": false,
        "input": ["text", "image"],
        "contextWindow": 32768,
        "maxTokens": 4096
      }]
    }
  }
}
```

실제 모델 ID는 서버의 `/v1/models`로 확인합니다. 이미지·추론 지원과 한도는 모델에 맞게 설정합니다. 인증 서버는 pi가 지원하는 환경변수 참조(예: `$MODEL_API_KEY`)를 사용하세요. `apiKey: "local"`은 인증 없는 로컬 서버에만 쓰는 자리표시자입니다. 호환성 옵션은 해당 서버에서 확인한 값을 넣습니다.

시작 시 provider/model을 강제하지 않으며 pi의 저장된 선택과 명시적 `--provider`/`--model` 옵션을 따릅니다. 기본 Ollama는 `nyatinorma.json` 설정으로 추가 등록하는 선택지입니다. 서버를 추가한다고 기존 Ollama가 내려가거나 설정이 바뀌지 않습니다.

THINK는 pi의 provider 연결을 사용합니다. SELECT도 현재 선택된 모델을 사용하며, OpenAI 호환 경로는 pi의 인증·주소·추론 호환 설정을 재사용합니다. 네이티브 Ollama와 OpenAI Chat Completions logprobs 경로를 지원하고, logprobs 누락/불완전한 점수는 실행 없이 THINK로 반환합니다. 그 밖의 API는 THINK/직접 행동을 사용할 수 있지만 SELECT는 지원 오류를 알립니다. 다른 서버로 자동 대체하지 않습니다.

## 입력 드라이버와 다른 프로그램 격리

기본 드라이버는 **기존 `cua-driver mcp`**입니다. nyatinorma가 소유하는 MCP 클라이언트와 무작위 고유 세션 이름을 사용합니다. 종료할 때 자기 세션과 클라이언트만 정리하며, 공용 데몬의 종료/재시작/업데이트/전역 설정 변경 도구는 호출할 수 없습니다. 다른 에이전트의 로그인·설정·설치본을 수정하지 않습니다.

macOS 캡처와 클릭은 cua-driver **0.9.0**에서 시험했습니다. 새 환경에서는 Cua 설치와 해당 앱의 macOS 권한 설정이 필요합니다. 일부 macOS iPad 앱은 백그라운드 클릭에 `cuaModifiers:["cmd"]`가 필요할 수 있습니다. 이 옵션은 호출 인자로만 전달하고 드라이버 전역 설정을 바꾸지 않으며 Windows에서는 보내지 않습니다.

**드래그는 별도 어댑터로 분리했습니다.** 시험한 macOS Cua 버전은 백그라운드 드래그를 거부합니다. 지원 범위는 [Cua 지원표](https://github.com/trycua/cua/blob/main/libs/cua-driver/docs/action-support.md)를 확인하세요. `dragDriver:"macos-bridge"`를 명시하면 드래그만 `Nyatinorma Bridge.app`에 보냅니다. `ny_drag`, SELECT의 드래그 모두 같은 어댑터를 사용합니다. Cua가 캡처한 창의 PID·ID·위치·크기를 브리지와 대조한 뒤 background 입력을 보내며, 결과는 Cua 이미지로 검증합니다. macOS 시험에서 목록 드래그, 커서 위치와 활성 앱 유지를 확인했습니다.

macOS 브리지가 필요하면 Xcode Command Line Tools의 Swift 컴파일러로 `npm run build:native`를 실행합니다. 생성된 `Nyatinorma Bridge.app`에 시스템 설정의 손쉬운 사용·화면 기록 권한을 허용해야 합니다. 빌드된 앱은 소스 저장소에 포함하지 않습니다. 공용 Cua 설치본을 수정하지 않습니다.

`nyatinorma.json`의 주요 설정:

- `driver:"cua"`: 기본 캡처·클릭 드라이버입니다. 자체 브리지 전체 기능은 `"macos-legacy"`를 명시한 경우에만 사용하며 자동 fallback은 없습니다. 드래그는 아래 별도 설정으로 선택합니다.
- `dragDriver:"macos-bridge"`: macOS에서 드래그만 별도 브리지로 보냅니다. 기본값 `"cua"`는 Cua만 사용하며 macOS의 미지원 드래그를 거부합니다. Windows에서는 항상 Cua 드래그를 사용하고 macOS 브리지를 실행하지 않습니다.
- `cuaDriverPath`: 기존 실행 파일 또는 프로젝트 전용 실행 파일의 경로. 기본 `cua-driver`.
- `targetApp`: 대상 창의 앱 이름 또는 정확한 제목. 각자 설정하며 기본값은 비어 있습니다.
- `targetPid`, `targetWindowId`: 대상이 여러 개일 때 명시적으로 지정할 수 있습니다. PID/창 ID는 앱 재시작 후 바뀔 수 있습니다.
- `cuaModifiers`: macOS용 입력 보조키. 기본값은 `[]`이며 대상 앱에 필요한 경우에만 지정합니다.

캡처는 지정 창 하나만, 입력은 `delivery_mode:"background"`만 사용합니다. foreground로 자동 전환하지 않습니다. 게임 창을 최소화하거나 닫지 마세요. 드라이버가 입력을 전달했다는 응답만으로 클릭 성공을 판단하지 않고, 실행 후 이미지를 다시 확인합니다. Cua가 반환하는 AX/UIA 텍스트는 모델에 전달하지 않습니다.

**Windows:** TUI/상태 관리/이미지 처리와 Cua MCP 어댑터는 Windows를 대상으로 작성했습니다. Windows용 cua-driver 및 접근 가능한 Ollama 서버가 필요하며, Windows의 게임/에뮬레이터 창에 맞게 대상을 지정해야 합니다. 현재 실기 검증은 macOS이며 Windows 게임 입력은 아직 미검증입니다. 원격 Ollama 서버에 `ollamaUrl`로 연결할 수 있지만, 이 프로젝트가 서버의 네트워크 설정을 변경하지는 않습니다. [Cua Windows API](https://cua.ai/docs/reference/cua-driver/mcp-tools-windows)

별도 버전이 필요하면 `cuaDriverPath`로 실행 파일을 지정하는 구조입니다. 프로젝트는 Cua를 자동 설치·업데이트하지 않습니다. 자체 브리지 전체 기능은 `driver:"macos-legacy"`를 명시한 경우에만 사용합니다. 드래그만 필요하면 `dragDriver`를 설정하세요.

macOS에서는 MCP 세션은 별개지만 Cua 데몬은 기존 설치본을 공유합니다. 따라서 별도 실행 파일 경로 지정만으로 데몬까지 격리되는 것은 아닙니다. 향후 드라이버 수정이 필요하면 독립 서비스 주소·앱 식별자·권한 소유자까지 분리해서 검증해야 합니다.

## THINK / SELECT

- **THINK:** pi 일반 대화·이미지 도구 루프. 모델은 `ny_reasoning`으로 다음 계획 요청의 추론을 켜거나 끌 수 있고, 후보 정의 오류가 연속 두 번 나면 하네스도 추론을 켭니다. 이 설정은 현재 pi 세션에만 적용됩니다. 선택된 pi provider의 스트리밍으로 목표, 관측, 후보와 복구 계획을 만듭니다. Ollama 네이티브 연결도 선택할 수 있습니다.
- **SELECT:** 확장의 짧은 루프. 현재 선택된 provider에 화면 이미지와 후보 설명을 보내고 추론을 끈 1토큰 `logprobs`를 사용합니다.
- **ACT:** `ny_act(goal, doneWhen, constraints)`는 사전에 작성한 flow 없이 작은 목표를 수행합니다. 내부에서 짧은 JSON 후보를 만들고 SELECT로 재사용하며, 새 화면에서는 후보를 다시 구성합니다. 클릭은 locate로 확인하고 드래그는 관측한 영역에서 실행합니다. 후보 생성은 planner 추론 설정을 변경하지 않습니다.
- 후보 세트의 `purpose`는 이번 화면에서 할 일입니다. 예를 들어 전체 목표는 별 3개 클리어여도 지금 목표는 "전투 목록을 열어 별 수 확인"입니다. SELECT에는 두 목표를 함께 전달합니다.
- **OCR을 사용하지 않습니다.** 모델이 게임 창 이미지와 crop을 직접 읽고 시각적 대상을 지정합니다. Cua의 AX/UIA 결과는 버리고 이미지와 창 메타데이터만 사용합니다.
- 후보 세트의 `visualAnchors`는 제목·선택된 탭·팝업 테두리 등 정적인 이미지 영역 1~4개입니다. 실제 관측에서 화면 앵커와 대상 템플릿을 추출하고, 모델 응답을 받은 후 새 화면에서 다시 비교합니다. 단색 앵커는 거부합니다.
- 대상 비교는 ±2픽셀의 렌더링 오차만 허용합니다. 더 크게 움직이거나 이미지가 달라지면 THINK로 돌아가 확대 관측 후 후보를 새로 만듭니다. 이미지 비교는 의미 이해를 보장하지 않으므로 SELECT에도 화면을 전달합니다.
- 기존 OCR 기반 세트는 자동 실행하지 않고 새 이미지 기반 세트로 다시 작성하도록 안내합니다. 과거 버전은 기록으로 보존합니다.
- 정밀 클릭에는 4×4 격자를 사용할 수 있습니다. `ny_observe`에서 `grid:true`로 A1~D4 칸을 보고, `regionPath:["C4"]`로 확대합니다. 다시 D3 칸을 선택하면 `regionPath:["C4","D3"]`를 후보에 넣습니다. 코드가 전체 창 좌표를 계산하므로 모델이 x+width 같은 산술을 할 필요가 없습니다. 격자는 모델에게 보여주는 이미지에만 그리며, 원본·템플릿은 변경하지 않습니다. `visualAnchorRegions`도 같은 경로를 받습니다.
- 셀 중앙 외의 위치는 `gridPoint:{regionPath:["C4"],x:0.2,y:0.8}`처럼 지정합니다. 이는 **C4 내부에서 왼쪽으로부터 20%, 위에서부터 80%**이며, 전체 창 좌표 변환은 코드가 처리합니다. `ny_drag`, SELECT 후보와 flow 행동에서 동일하게 사용하며 드래그 도착점에는 `toGridPoint`를 씁니다. 기존 `point`는 전체 창 기준, `regionPath` 단독은 셀 중앙입니다.
- `ny_preview`에 `snapshotId`와 같은 좌표 인자를 주면 **클릭 없이** 십자선·좌표를 표시한 전체 이미지와 확대 이미지를 돌려줍니다. 위치가 맞으면 같은 인자를 행동 도구에 넘깁니다. 선택적인 확인 도구이며, 원본 캡처나 관측 시각을 변경하지 않고 실제 행동의 화면 검증도 생략하지 않습니다.
- `ny_time`은 현재 현지 시각·시간대·UTC를 조회합니다. `nextLocalTime:"03:00"`을 주면 컴퓨터 시간대에서 다음 해당 시각의 날짜까지 계산합니다. `operation:"set_deadline"`과 함께 주면 현재 실행의 일회성 마감으로 저장합니다. 날짜가 정해진 제한은 `stopAt`에 시간대 오프셋을 포함한 ISO 시각을 지정하며, 지난 시각도 그대로 만료 처리합니다. 마감은 재시작·재개 후에도 유지되고 자동 연장되지 않습니다. 반복 실행과 입력 직전에 검사하여 늦게 도착한 모델 응답이 새 클릭을 보내지 못하게 합니다. 이미 보낸 입력과 **게임 자체 자동진행**은 중단하지 않으므로, 자동진행까지 끄려면 마감 전에 해당 UI 작업을 수행하도록 요청해야 합니다. 사용자 지시에 따른 해제는 `operation:"clear_deadline"`입니다.
- `intent`는 자유로운 행동 설명이며 작업 전용 enum이 없습니다. 추가 관측 정보는 후보의 `data` 객체에 담습니다.
- 확대는 원본 스크린샷 crop입니다. 확대 결과에는 전체 창 이미지도 함께 제공해 화면 밖 번호나 상태를 추정하지 않도록 돕습니다. 모든 저장 좌표는 **전체 창 기준 0–1**이며 Cua 캡처 픽셀로 변환한 뒤 드라이버가 실제 입력 좌표로 변환합니다.
- Cua 캡처의 원본 크기와 픽셀 좌표를 그대로 보존합니다. Retina/DPI 변환은 드라이버가 담당합니다.
- 매 모델 요청에는 가장 최근 관측 묶음의 이미지를 전달합니다. 한 번에 여러 crop 도구를 호출했다면 그 묶음은 모두 유지해 별 판독의 근거가 누락되지 않게 합니다. 이전 묶음은 ID·텍스트와 로컬 원본으로 남아 다시 확대할 수 있습니다.
- 이미지 입력은 지정된 **게임 창**과 그 창의 crop/격자 이미지입니다. 바탕화면 전체를 보내지 않습니다. 이미지 옆에 관측 ID, 전체/확대 이미지 순서, 영역 좌표를 명시합니다. 작업 지침·도구 정의·대화 기록도 텍스트로 입력됩니다.
- 화면 변경, 불완전한 top-k, 낮은 선택 점수, 드래그 후에는 THINK로 돌아갑니다.

확률은 **보정되지 않은 토큰 점수**입니다. `selectMinMass`·`selectMinMargin`·템플릿 임계값은 초기 보수적 설정이며 실제 성공률을 뜻하지 않습니다. 모든 후보가 top-k에 없으면 실행하지 않습니다. 입력 prefill과 공유 Ollama의 대기 시간은 1토큰 선택으로 사라지지 않습니다.

공유 서버의 대기를 고려해 `ollamaTimeoutSeconds`는 기본 **600초(10분)**, SELECT 구간의 `maxRunSeconds`는 **900초(15분)**입니다. `nyatinorma.json`에서 변경한 뒤 TUI를 다시 열면 반영됩니다. 긴 요청 중에도 Escape로 취소할 수 있으며, 응답을 오래 기다린 경우에도 입력 직전에 화면과 창 좌표를 재검증합니다. 서버 오류의 자동 재시도는 꺼져 있어 실패가 보이면 원인을 확인하고 다시 요청합니다.

## 작업과 개선

**스킬 패키지**는 앱의 재사용 지식·프리셋·후보 세트·근거 자료를 묶습니다. **실행 기록**은 이번 계획·진행·후보·로그이며 **대화**는 pi 세션입니다. 시작할 때 실행 생성이나 프리셋 선택을 요구하지 않습니다. 모델은 현재 임시 기록에서 바로 작업하고, 필요하면 `ny_run configure`로 프리셋을 적용하거나 이름을 붙입니다. 이때 기록 ID와 진행은 보존됩니다. `/preset`은 별도 실행을 명시적으로 만들 때 사용합니다.

새 대화·`/tree`·`/fork`에는 이전 진행이 섞이지 않은 임시 기록을 자동으로 만듭니다. `/resume`은 그 대화의 기록 연결을 복원합니다. 과거 대화로 돌아가도 게임 상태는 돌아가지 않으므로 입력 전에 새 화면을 관측합니다. 같은 실행을 여러 터미널에서 동시에 변경하는 것은 잠금으로 막습니다. 임시 기록은 작업 지시가 아니며, 질문만 하면 게임을 조작하지 않습니다.

지식은 **공통 조작 → 앱 공통 → 상황별**로 구분합니다. 공통/앱 지식과 상황 목록을 기본 제공하고, 모델은 `ny_knowledge use`로 현재 상황을 선택합니다. 상황별 지식은 다른 작업에 무조건 주입하지 않습니다. `read`로 검색·조회하고 `remember`로 새 지식을 보존합니다. 스크린샷이 있는 메모는 `observed`, 아직 가설이면 `hypothesis`로 저장하며, `supersedes`로 잘못된 메모를 대체해도 원문은 남습니다. `evidence`로 과거 근거 이미지를 다시 볼 수 있습니다. 오래된 근거는 현재 게임 상태를 뜻하지 않습니다.

전체 메모를 매번 전송하지 않고 짧은 최근 요약만 주입하며 필요할 때 검색합니다. 성공 후에는 재사용할 발견을 저장하고 필요하면 프리셋을 만든 뒤 후보 세트를 검증·등록하도록 모델에 지시합니다. 저장은 도구 호출로 이루어지며, 모델의 발견이나 이미지 판독이 자동으로 정확해지는 것은 아닙니다.

기존 태스크별 진행/계획/후보/로그는 원본을 보존한 채 `이전 기록 · …` 실행으로 가져옵니다. 과거 테스트가 새 대화에 강제로 주입되지 않습니다. 이력 기능은 입력창 맨 위의 ↑, PageUp/PageDown, `/tree`, `/fork`, `/resume`을 사용하며 `/help`에도 표시합니다.

작업 정의와 select set 수정본은 이전 버전을 보존합니다. 모델은 `ny_history`로 실패와 사용자 피드백을 읽고 `ny_define_set`으로 수정하고, 과거 관측에 `validate`를 실행하거나 `rollback`으로 되돌릴 수 있습니다. 이는 **작업·탐색 정책의 개선**이지 가중치 학습이나 정확도 향상 보장이 아닙니다. `validate`는 화면/대상 재인식 검사이며 게임 성공률 검증은 아닙니다.

`ny_plan`은 현재 구간의 단계·진행 중 항목·완료 근거·막힌 이유·미확인 항목을 실행별로 저장합니다. 모델 요청마다 최신 계획과 짧은 진행 요약을 다시 제공합니다. `/plan`으로 사람이 확인하고 `/feedback`으로 교정할 수 있습니다. 계획 완료는 스크린샷 참조가 필요하지만, 이미지 의미를 자동 검증하거나 전투 별 기록을 대신하지 않습니다. 장기 작업은 구간별로 계획을 갱신합니다.

`ny_block`은 모델이 구체적인 진행 불가 사유를 판단했을 때 쓰는 종료 도구입니다. 사유·시도한 방법·진행 상황·필요한 개입을 저장하고 현재 에이전트 실행을 종료하므로, 보고서를 쓰기 위한 추가 추론도 발생하지 않습니다. 시도 목록은 비워도 되며 정상 대기나 필요한 반복 횟수만으로 자동 발동하지 않습니다. 중단 상태는 재시작·재개 후에도 유지되고, 후속 입력과 모델의 새 실행 생성 우회도 차단합니다. 사용자 질문에 대한 설명과 기록 조회는 가능합니다. 준비되면 **`/play [교정 내용]`**으로 같은 기록에서 재개하며 새 화면부터 확인합니다. 기존 마감 시각은 그대로 유지합니다. 막힘 판단은 모델에 의존하지만, `ny_block` 호출 후 종료는 코드가 수행합니다. 게임 자체 자동진행을 끄는 기능은 아닙니다.

세트는 실행별로 독립됩니다. `ny_history publish`로 관측 검사를 통과한 세트와 검증 이미지를 스킬 안의 프리셋 라이브러리에 저장하면 새 실행이나 명시적 프리셋 적용 때 재사용합니다. 기존 실행의 세트를 덮어쓰지 않습니다. 임시 기록에서 만든 세트를 공유하려면 재사용 프리셋에 연결합니다. 모델의 작업 상태에는 현재 세트 목록이 표시되며, 반복 화면은 SELECT를 우선 검토하고 서로 다른 첫 방문 화면의 클릭은 `ny_locate(click:true)`를 사용합니다. 잘못 만든 세트는 `ny_history retire`로 비활성화할 수 있습니다. 과거 버전은 보존합니다.

계획을 저장하고 실행 중 다시 알려주는 구성은 [oh-my-pi의 todo tracker](https://github.com/can1357/oh-my-pi/blob/main/packages/coding-agent/src/session/todo-tracker.ts)를 참고했습니다. 기존 pi 확장으로 구현하므로 oh-my-pi/Bun 추가 설치가 필요하지 않습니다.

`ny_checkpoint`는 `snapshotId`와 `note`, 선택적인 `key`·`data`·`state`로 관측한 진행을 기록합니다. 작업에 필요한 필드는 모델이 정의합니다. 예를 들어 전투라면 난이도와 별, 문서라면 페이지와 검토 상태를 담을 수 있습니다. 기존 진행은 `legacy`에 원문 그대로 보존됩니다.

실행 코드에는 특정 게임·시즌·별·CLEAR·전투 횟수에 따른 분기가 없습니다. 작업별 기준은 사용자의 지시와 실행 중 모델이 저장한 스킬/프리셋 **자료**에서 읽습니다. 게임별 기본 프리셋이나 지식은 제공하지 않습니다. 코드가 검사하는 것은 관측의 최신성, 화면/대상 이미지, 좌표/창, 반복 입력과 취소 등 공통 조건입니다. 이미지의 의미와 지침 준수는 모델 판단에 의존합니다.

## 즉석 실행과 저장된 절차

`ny_act`는 작은 목표와 눈으로 확인할 수 있는 종료 조건을 받습니다. 예를 들어 `{"goal":"목록에서 요청한 항목을 찾아 연다","doneWhen":"해당 항목의 상세 화면이 보인다","constraints":["내용은 변경하지 않는다"]}`처럼 요청합니다. 좌표나 미리 작성한 행동 순서는 받지 않습니다. 현재 pi 모델·provider를 사용하며 별도 서버나 의존성을 추가하지 않습니다.

내부 후보 생성은 추론을 끈 짧은 JSON 출력이며, 후보 선택·좌표 탐색·화면 확인에는 1토큰 SELECT를 사용합니다. 후보는 최대 4개이고 기본 예산은 입력 20회, 후보 구성 6회, 설정된 `maxRunSeconds`입니다. 대기·재구성만 계속되는 경우도 별도 결정 횟수와 시간 예산으로 끝납니다. 한 번의 호출 안에서 방문한 화면과 최근 행동을 기억하고 확인된 클릭 위치를 재사용합니다. 새 화면에서 후보를 바꿀 수 있지만 사용자가 지정한 범위를 넓히지는 않습니다.

클릭 후에는 기대 결과를 확인하고, 불명확하면 `outcome_unconfirmed`로 반환합니다. 클릭 자체를 반복하지 않습니다. 완료는 새 화면에서 한 번 더 확인한 `local_goal_observed`이며, 전체 사용자 태스크 완료를 의미하지는 않습니다. 중간 캡처·후보·실행 기록은 로컬에만 저장되고 상위 대화에는 요약과 마지막 화면을 전달합니다. 기록은 학습 자료이며 자동으로 검증된 flow로 승격하지 않습니다.

`ny_execute_flow`는 저장된 상태·후보·전이를 따라 반복합니다. `ny_act`와 같은 위치 확인·입력 실행기를 사용하지만 정의되지 않은 화면에서는 상위 모델로 돌아옵니다. 기존 flow/SELECT의 클릭 좌표도 더 이상 독립적인 근거로 쓰지 않습니다. `target`의 시각적 설명을 locate로 확인하며, 과거 정의에 `target`이 없으면 `label`을 사용합니다. 모호한 옛 label은 구체적인 target으로 수정해야 합니다. 드래그 정의는 기존 형식을 유지합니다.

기본 도구는 실행·관측·시간·진행/지식 기록 위주로 노출합니다. `ny_tools(operation:"enable", group:...)`로 `flow`(절차 작성·보존), `legacy`(후보 세트·기록), `manage`(프리셋), `inspect`(미리보기·추론 설정)를 불러올 수 있습니다. 불러온 도구는 세션 동안 유지하며, 매 턴 숨겼다 나타내지 않습니다. 새 세션과 재시작에서는 기본 목록으로 돌아갑니다.

## 관측 재확인과 연결 복구

`ny_observe(snapshotId, verify:true)`는 과거 이미지와 현재 화면이 같은 작업 상태인지 내부에서 확인하고 현재 이미지를 반환합니다. 동일 픽셀이면 모델 호출을 생략하고, 다르면 비교 이미지로 YES/NO/UNCERTAIN SELECT를 합니다. 입력 직전에는 SELECT가 확인한 대상과 가까운 주변의 RGB 변화만 검사합니다. 넓은 anchorRegion은 의미 판정의 참고 영역이며 픽셀 고정 조건이 아닙니다. 배경·캐릭터 애니메이션 때문에 화면 전체가 정지하기를 기다리지 않습니다. 대상이 실제로 달라졌으면 내부에서 한 번 더 확인하고, 불명확할 때만 현재 이미지와 함께 반환합니다. 창의 PID·ID·크기·위치가 달라졌거나 판단이 불명확하면 기존 좌표를 실행하지 않습니다. 시간 경과 자체를 화면 변경으로 취급하지 않습니다. 기록 이름·마감 시각 변경은 기존 관측을 무효화하지 않으며, 다른 실행·작업 범위로 전환하거나 중단 후 재개할 때는 새 관측이 필요합니다.

Cua 요청 제한은 `desktopTimeoutSeconds`로 설정하며 기본 180초입니다. 읽기 전용 캡처가 타임아웃이면 새 파일로 한 번만 재시도합니다. 새 화면을 얻지 못한 상태에서는 같은 화면이라고 판정할 수 없습니다. Cua 세션 만료로 입력이 **실행 전에 거부됐음이 확인된 경우**에는 해당 private 세션을 복구하고 화면 SELECT 검증 후 한 번 재시도합니다. 반대로 입력 타임아웃은 실행 여부가 불명확하므로 자동 재전송하지 않습니다. 공유 Cua 데몬이나 다른 프로그램의 세션은 재시작하지 않습니다.

## 격자 좌표 탐색

`ny_locate(target, snapshotId, click=false)`는 새 클릭 대상의 위치를 찾을 때 우선 사용하는 도구입니다. 버튼을 알아보더라도 좌표를 새로 추정해야 한다면 planner가 픽셀·비율·crop 오프셋을 계산하지 않고 이 도구에 맡깁니다. 내부 1토큰 SELECT로 긴 좌표 추론과 planner 왕복을 줄이도록 안내합니다. A–I로 표시한 3×3 격자에서 클릭 지점을 포함한 칸을 SELECT로 선택하고, 그 칸의 1.5배 영역을 원본 이미지에서 확대합니다. 주변 문맥이 사라지면 이전 단계로 축소할 수 있습니다. 격자 선택과 좌표 확정은 별도 요청입니다. 확대·축소는 입력을 보내지 않으므로 여러 칸의 점수가 비슷하거나 일부 top-k 후보가 누락되어도 알려진 점수로 탐색할 수 있습니다. 좌표는 격자 없이 십자선을 보여주고 YES/NO/UNCERTAIN 세 후보만 비교하여 확인합니다. 확정에는 완전한 점수와 기존 점수 차이 기준이 필요합니다. 기본·최대 예산은 이동·검증을 포함한 SELECT 20회입니다. `maxSteps`를 생략하면 20회를 사용합니다. 십자선이 목표 안의 적절한 위치라는 확인을 받아야 전체 창 기준 0–1 좌표를 반환합니다. 탐색 예산·원본 해상도 한계·불확실성으로 끝나면 좌표를 반환하지 않습니다. 기존 4×4 `regionPath`는 시작 영역을 지정하는 선택 사항이며 내부 격자와 별개입니다. MOVE 모드에서는 확대 배율을 유지하며 십자선만 상하좌우·대각선 8방향으로 옮깁니다. 초기 이동량은 현재 영역의 1/8이고, 필요하면 절반씩 줄여 원본 1픽셀 수준까지 조정합니다. 확대 한계에서도 이동할 수 있으며 매 이동 뒤 별도 좌표 검증을 거칩니다. 실제 마우스를 움직이는 기능은 아닙니다.

기본값은 좌표 반환뿐입니다. 1회 클릭은 `click:true`로 요청하며 `expectation`이 필요합니다. `anchor` 또는 `anchorRegion`은 선택적인 문맥 힌트입니다. 좌표 확인과 새 화면·창·대상 검사를 통과해야 클릭합니다. 클릭 요청 결과는 `inputSent`와 `clicked`로 입력 전송 여부를 명시합니다. `reason:input_not_sent`이면 클릭되지 않았고, `input_sent`는 입력 전송만 뜻하며 성공 판정은 아닙니다. 반환된 현재 이미지를 재사용하고 같은 이미지를 얻으려고 다시 observe할 필요는 없습니다. 직접 좌표 클릭 도구는 제공하지 않습니다. 좌표 반환 모드는 위치 확인·미리보기에 사용할 수 있으며, 오래된 화면에서 찾은 좌표를 현재 상태로 간주하지 않습니다.

탐색은 본 대화 전체를 복제하는 pi `/fork`가 아니라, 시각적 목표·짧은 선택적 `constraints`·기준 화면으로 시작하는 내부 대화 분기입니다. 전체 작업 이력은 복제하지 않으며, 작업 정책과 다음 행동의 선택은 부모 planner가 담당합니다. 확대는 기존 요청/응답 뒤에 추가하고 축소는 부모 분기의 공통 prefix로 되돌리고, 이미 실패한 영역은 다시 고르지 않도록 기록합니다. paged/prefix cache가 있다면 이를 재사용할 수 있지만 캐시 적중을 보장하거나 서버 설정을 바꾸지는 않습니다. 중간 이미지와 결정 기록은 로컬 `.nyatinorma/locate/`에 남기며, 주 대화에는 최종 결과와 근거 이미지만 전달합니다. 클릭한 경우에는 행동 후 화면을 전달합니다.

## 데이터와 설정

`nyatinorma.json`은 로컬 전용이며 Git/배포에 포함하지 않습니다. 새 설치는 `nyatinorma.example.json`을 복사하고 주소·모델·대상 창을 설정합니다. `NYATINORMA_OLLAMA_URL`/`NYATINORMA_MODEL` 환경변수도 지원합니다. `contextWindow`·`maxTokens`·`reasoning`은 pi에 등록할 모델 메타데이터이며 Ollama의 상주/컨텍스트 설정을 변경하지 않습니다.

커스텀 provider의 `contextWindow`는 `.nyatinorma/pi/models.json`에서 실제 서버 한도와 맞춥니다. OpenAI 호환 서버가 `/models`에 `max_model_len`을 제공하면 시작·모델 선택·사용자 요청 시 확인하여 현재 실행의 한도를 낮춥니다(조회 결과는 60초 캐시). 사용자 설정보다 높이지 않으며, 한도를 제공하지 않는 서버는 등록값을 사용합니다. 등록 파일과 서버 설정은 자동 변경하지 않습니다. 모델 등록이나 확장 코드를 수정한 뒤에는 실행 중인 TUI에서 `/reload`로 다시 읽습니다.

긴 세션은 pi의 compaction 경계에서 줄입니다. 스크린샷을 매 요청마다 이동식으로 제거하지 않고, compaction 사이에는 과거 메시지와 이미지를 유지하여 prefix cache 재사용을 방해하지 않습니다. 시작·모델 선택 시에는 이전 모델의 토큰 사용량을 그대로 믿지 않고 pi의 추정기로 다시 계산하며, 새 한도의 compaction 기준을 넘으면 정리를 실행합니다. 일반 실행 중에는 pi의 임계치·컨텍스트 초과 복구·`/compact` 호출이 같은 정책을 사용합니다.

정리 방식은 **오래된 도구 결과·이미지 생략 → pi 의미 요약 → 요약 실패 시 오래된 실행 내역 절단** 순서입니다. Compaction 경계에서 최근 원본 구간을 약 4K 추정 토큰으로 좁히되, 최신 이미지 관측과 도구 호출/결과 묶음은 보존합니다. 묶음 자체가 크면 4K를 넘을 수 있습니다. 기계적 정리 기록은 컨텍스트의 10% 또는 6K 중 작은 크기 이하로 제한하고, 두 번 연속 기계적으로 정리했다면 다음에는 의미 요약을 시도합니다. 전체 복구 목표는 `(contextWindow − reserveTokens) × 70%`이며, 현재 모델이 보고한 실제 사용량이 추정보다 크면 그 비율만큼 목표와 요약 예산을 낮춥니다. 이전 모델 또는 이전 compaction 전의 사용량은 보정에 쓰지 않습니다.

의미 요약은 이전 요약까지 병합하며, 요약용 추론은 끄고 기존 pi provider를 사용합니다. 출력 토큰 한도에 잘린 요약은 저장하지 않습니다. 실패하거나 절감량이 부족하면 사용자 지시·이전 요약·최근 원본 구간을 보존하면서 오래된 실행 내역을 제거합니다. 이마저 충분히 줄이지 못하면 이유를 표시하고 중단합니다. 각 단계는 경계당 한 번만 시도합니다. `/compact 추가 지시`는 도구 정리를 건너뛰고 의미 요약부터 요청합니다.

원본 세션·캡처는 보존됩니다. 모델은 `ny_recall`로 원본 텍스트를 검색하거나 특정 기록의 이미지 한 장을 다시 읽을 수 있고, `ny_observe(snapshotId)`로 저장된 화면을 볼 수 있습니다. 기계적 절단은 의미 요약보다 정보를 더 잃을 수 있어 TUI에 경고합니다. 토큰 추정은 서버 tokenizer와 다르며 컨텍스트 한도 보장의 대체물이 아닙니다. [OMP의 compaction 설계](https://github.com/can1357/oh-my-pi/blob/main/docs/compaction.md)에서 방법별 효과 판정과 다음 방법으로 넘어가는 원칙을 참고했습니다. OMP 전체 실행 순서·백그라운드 선행 요약을 이식한 것은 아니며, OMP 소스나 추가 의존성을 포함하지 않습니다.

`nyatinorma.json`: Ollama 주소/모델, Cua 실행 경로/대상 창, 실행 예산, 선택 기준. 기존 Ollama 설정이나 전역 pi 설정을 변경하지 않습니다. pi 설정은 `.nyatinorma/pi`에 격리되고, 사용자가 바꾼 테마·UI·추론 설정을 시작 시 덮어쓰지 않습니다.

`.nyatinorma/skills/computer-use`: 공통 지식. `.nyatinorma/skills/<knowledgeAppId>`: 앱 패키지로 `SKILL.md`, `notes/`, `presets/`, `sets/`, `evidence/`를 포함합니다. 프리셋·세트의 기존 파일은 다음 시작에 원본을 보존하고 복사하며 이후 패키지 쪽을 사용합니다. 다른 앱은 `knowledgeAppId`로 패키지를 지정하거나 bundleId 기반 이름을 사용합니다. 패키지는 지식 자료이며 모델·드라이버·앱 설치를 포함하지 않습니다.

`.nyatinorma/runs/<실행ID>`: 자동 생성된 기록, 계획, 진행, 후보, 로그. `.nyatinorma/pi/sessions`: 대화와 실행 연결 이력. `.nyatinorma/captures`: 원본 이미지와 메타데이터. `.nyatinorma/feedback.jsonl`: 교정 기록. 실행 완료 상태는 스킬로 복사하지 않습니다. 새로 저장한 지식/공유 세트의 근거는 패키지 내부 상대 경로로 보존합니다. 기존 실행의 모든 과거 이미지를 패키지로 옮기지는 않습니다.

## 검증

이번 변경의 범위와 실제 화면 검증은 [구조·설정·개인정보 점검](docs/architecture-and-privacy.md)을 참고하세요. Windows 실기와 장기 자율 주행은 아직 미검증입니다.

임시 기록·스킬 계층·시즌 선택 수정은 [지식과 기록 검증](docs/knowledge-and-sessions.md)에 정리했습니다. 실행 중인 세션은 변경하지 않으며 새 코드는 다음 시작부터 적용합니다.

```sh
npm test
npm run typecheck
npm run probe                 # 기존 모델의 SELECT/logprobs 확인, 게임 입력 없음
npm run observe               # 실제 게임 창 이미지 캡처, 입력 없음
npx tsx src/cli.ts vision-probe  # 같은 Ollama 모델에 게임 이미지 전달, 입력 없음
```

기본 pi 도구에서는 범용 shell/file 편집을 제외하고 작업·관측·정의·실행·기록 도구를 제공합니다. TUI의 핵심은 pi를 재사용하며 게임 실행 정책은 이 프로젝트의 TypeScript 확장에 있습니다.
