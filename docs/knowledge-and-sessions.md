# 임시 기록과 재사용 지식

새 대화는 선택 메뉴 없이 임시 기록을 만든다. 이는 기록을 담을 공간이며 작업 지시나 입력 권한이 아니다. `/save 이름`으로 이름을 붙이고 `/runs`로 다시 연다. 이름 변경과 프리셋 적용은 같은 기록 ID와 진행을 보존한다. 새 대화, 분기, 대화 트리 이동은 이전 진행을 이어받지 않는 새 기록을 만든다. 대화 재개는 원래 연결을 복원한다.

## 저장 구조

```text
.nyatinorma/
  skills/
    computer-use/SKILL.md, notes/, evidence/
    <knowledgeAppId>/
      SKILL.md
      notes/                 앱 공통 또는 상황별 메모, 교정 이력
      presets/               사용 중 모델이 생성한 작업 정의와 버전
      sets/<preset-id>/      재사용 후보 세트와 버전
      evidence/              새로 보존한 지식·공유 세트의 근거 이미지
  runs/<id>/                 이번 계획·진행·후보·로그
  pi/sessions/               대화
```

공통과 앱 지식은 제한된 요약으로 제공한다. 모델은 상황 목록을 보고 필요한 상황을 선택하고 더 자세한 메모를 검색할 수 있다. 다른 상황의 메모는 함께 주입하지 않는다. 지식 메모는 관측 근거가 있으면 observed, 없으면 hypothesis로 표시한다. observed는 근거 파일의 존재를 뜻하며 이미지 내용의 독립 검증을 뜻하지 않는다. 틀린 메모는 supersedes로 대체하고 이전 메모는 보존한다.

스킬 폴더는 해당 지식·프리셋·후보·새로 보존한 근거를 함께 옮길 수 있다. 공통 지식을 함께 옮기려면 computer-use 폴더도 보존한다. 모델, 입력 드라이버, 앱 자체는 별도 환경 의존성이다. 기존 실행의 전체 스크린샷과 완료 상태는 포함하지 않는다.

게임별 기본 프리셋/지식은 제공하지 않는다. 이전 데이터 이관은 tasks/sets 원본을 보존하고 패키지로 복사한다. 패키지에 이미 있는 파일은 덮어쓰지 않는다. 서로 다른 버전의 프로세스에서 동일한 프리셋을 동시에 수정하지 않는다.

## ny_act와 SELECT

ny_act와 SELECT는 공통 관측·좌표·창 식별·화면/대상 변경·반복 입력 검사를 사용한다. 특정 게임/작업 ID, CLEAR·별·난이도·시즌·전투 횟수에 따른 실행 분기나 필수 필드는 없다. intent는 자유 설명이고 임의의 작업 정보는 data에 저장한다. 작업별 기준은 스킬/프리셋 자료에서 모델이 읽고 따른다.

ny_checkpoint는 key/data/state와 근거 화면을 받는 범용 구조다. 이전 진행 원문은 legacy로 보존한다. 코드가 이미지 의미나 작업 성공을 독립적으로 검증하는 것은 아니다.

서로 다른 화면의 첫 탐색은 ny_act를 사용할 수 있다. 반복 화면이나 이미 저장된 적합한 후보 세트는 ny_run_select를 우선 검토하도록 지시하고 현재 세트 목록을 작업 상태에 함께 제공한다. SELECT의 think:false/1토큰/logprobs 계산은 유지된다. 실제 모델이 지침을 항상 따르거나 더 빨라진다는 보장은 아니다.

## 검증 범위

격리 데이터와 모의 Ollama로 실제 pi RPC를 구동했다. 자동 임시 기록, 같은 ID로 이름 변경, 새 대화/분기 독립성, 재개, 모델의 ny_knowledge 저장/선택, 새 대화에서 앱 지식 보존과 상황 지식 분리를 확인했다. 이미지 원본을 지운 뒤에도 패키지 내부 근거를 읽는 테스트, 범위 밖 교정 거부, 이전 메모 보존, 프리셋/세트 이관 보존도 포함한다.

자유로운 intent/metadata가 도메인 필터에 걸리지 않고 잘못된 좌표는 계속 거부되는 회귀 테스트를 포함한다. 테스트는 격리된 임시 데이터와 모의 서버를 사용한다.
