# 작은 모델도 사용할 수 있는 sleepwalk 하네스

## 최우선 원칙 — 사용자가 확인한 방향 (2026-09-28)

목표는 LLM의 시각 판단 능력을 최대한 활용하는 Jev식 sleepwalk다. 후보를 마련하고 확률 SELECT로 장면 연속성·대상·행동·진행·완료를 판단하며, 작은 판단과 복구는 실행기 내부에서 이어간다. THINK는 후보로 표현할 수 없는 새 상황이나 목표 재설정에 사용한다. 픽셀 일치나 게임별 하드코딩으로 LLM 판단을 대체하거나, 의미적으로 확인한 YES를 픽셀 오차로 다시 거부하지 않는다. 코드는 입력 전달, 상태 보존, 취소·마감·창 식별 같은 실행상의 사실을 관리한다. 입력 후 결과도 시각 SELECT로 확인한다. 평가 기준은 적은 출력 토큰뿐 아니라 THINK 왕복과 중복 검증을 줄이면서 실제 목표를 달성하는 것이다.

상태: 2026-09-28 구현 반영. ACT·FLOW·WAIT 공통 실행기, 단계별 SELECT, 드래그 경로와 결과 검증, continuation 저장 및 도구 재배치를 구현했다. 아래는 구현의 기준이 된 설계이며, 실제 적용 범위와 남은 한계는 마지막 절에 기록한다. 기존 sleepwalk-design.md의 도구 배치와 제어 흐름을 대체한다.

## 1. 원하는 사용 경험

부모 모델이 “현재 목록에서 X를 찾아 열어라”라고 맡기면, 하네스가 위치 탐색·입력·확인·대기·작은 복구를 수행한다. 반환할 때는 완료 근거 또는 새로 필요한 판단을 알려준다. 좌표 계산, 자세한 사전 플랜, 절차 파일 작성은 실행의 선행 조건이 아니다.

최근 호출 70개 중 ny_locate가 35회, ny_act는 1회였다. 현재 ACT는 드래그 결과를 명시적으로 구분하지 않으며 flow는 별도 검증 루프를 가진다. 기능의 분절을 줄여 부모 THINK 왕복을 줄인다. 같은 작은 모델이 SELECT에서 화면을 오판할 가능성은 남는다. 출력 토큰 수만 줄이는 것을 성공으로 보지 않는다.

## 2. 도구 배치

| 기본 실행 도구 | 책임 |
| --- | --- |
| ny_observe | 작업 시작 또는 명시적 조사. ACT 전에 반드시 호출하는 절차로 만들지 않는다. |
| ny_act | 작은 목표를 받아 후보 구성·저장 절차 재사용·위치 탐색·입력·검증·복구 |
| ny_wait | 조건을 기다리는 명확한 단축 인터페이스. 공통 실행기를 사용하되 입력을 코드로 금지 |

기본 보조 도구는 ny_knowledge, ny_time, ny_block, ny_tools다. **기본 surface는 일곱 개**다. 익명 run과 실행 진행은 런타임이 저장한다. 상세 플랜·체크포인트 편집·run 관리·flow 편집은 추가 그룹에서 활성화한다. 기존 pi 명령과 TUI 이력은 유지한다.

- ny_execute_flow: 추가 flow 그룹으로 이동. 명시적 재현·진단에 유지하며, 일반 ACT는 적합한 절차를 내부에서 재사용한다.
- ny_locate, ny_preview: 추가 조사 도구. locate 기능은 공통 실행기의 내부 기능으로 계속 사용한다.
- ny_drag와 기존 세트 실행: 추가 호환 그룹. 공통 입력 상태·검증·결과 보고를 우회하지 못한다.
- 기존 ny_locate(click:true): 공통 실행기의 단일 입력 및 결과 확인 경로로 연결한다.
- 추가 그룹은 한 번 활성화하면 세션 동안 유지한다. 매 턴 schema를 교체하지 않는다.

**공통 실행기와 절차 재사용을 완성한 뒤 기본 노출을 바꾼다.** 저수준 도구부터 숨겨 불완전한 ACT를 강제하지 않는다.

## 3. 플랜 대신 짧은 계약

새 ACT는 시작 시 goal 하나만 필수다. until(눈으로 확인할 종료 조건)과 constraints는 선택이다. 예산은 설정 기본값을 쓰며 일반 호출마다 작성하지 않는다. 기존 doneWhen은 호환 어댑터에서 until로 해석한다.

시작 예: ny_act({goal:"현재 목록에서 X를 찾아 상세 화면을 연다",constraints:["현재 목록 안에서만 탐색한다"]})
재개 예: ny_act({resume: continuationId})
goal과 resume는 배타적이다.

부모 THINK가 작업의 의미와 범위를 결정한다. 실행기는 후보 생성과 함께 대상·허용 행동·탐색 범위·완료 증거를 짧은 계약으로 정규화한다. 긴 순서 계획이 아니다. 새 권한·클릭·다른 메뉴 탐색을 임의로 추가하지 않는다. 해석이 불명확하면 행동 전에 그 차이만 부모에게 묻는다. SELECT가 매번 긴 사용자 원문을 재해석하지 않도록 원 요청의 출처/revision과 명시적 제약을 함께 보존한다.

“찾는다”는 발견에서, “찾아 연다”는 대상 상세 화면 확인에서 끝난다. 조건이 추상적이거나 관측으로 판정할 수 없으면 needs_decision으로 반환한다. 거대한 전체 작업을 ACT에 숨기지 않고 관측 가능한 작은 목표로 맡긴다.

우선순위는 현재 사용자 요청·수정사항 → 현재 화면의 사실 → 실행 중인 작은 목표 → 과거 플랜·지식이다. ny_plan은 선택적인 메모이며 실행의 선행 조건이 아니다. 부모에게 현재 목표·확인된 진전·미해결 문제만 짧게 제공한다. 오래된 전체 플랜을 지키려고 현재 관측을 무시하지 않는다. 새 목표는 계약 revision을 바꾸지만 미확정 입력은 지우지 않는다.

## 4. 실행 구조와 책임

| 계층 | 책임 |
| --- | --- |
| 부모 THINK | 작은 목표, 의미·범위, 범위를 바꾸는 판단, 필요한 사용자 질문 |
| 후보 작성 | 필요한 화면에서 최대 네 후보를 짧은 JSON으로 생성. 현재 pi 모델/provider 사용 |
| 단계별 SELECT | 현재 단계에서 합법적인 선택지 중 하나. 새 계획이나 좌표 계산을 맡기지 않음 |
| 공통 실행기 | 전이, 입력 상태, 기억, 예산, 취소, 마감, 창 식별, 입력 잠금 |
| 위치 탐색/드라이버 | 시각적 대상·경로 확인, 좌표 변환, 기존 드라이버로 입력 |

ACT는 즉석 후보, FLOW는 저장 후보·전이, WAIT는 입력 없는 후보를 공급한다. 관측·입력·결과·복구 루프는 하나다. 정상 입력 사이 관측을 생략하지 않는다.

~~~mermaid
flowchart TD
    P[THINK: 작은 목표] --> C[짧은 계약과 후보]
    C --> O[관측과 단계별 SELECT]
    O -->|허용된 행동| G[대상과 경로 확인]
    G --> A[입력 한 번 전송]
    A --> V[결과 관측]
    V -->|효과 확인 · 목표 미충족| O
    V -->|대기 또는 국소 복구| R[기다림 · 확대 · 보정]
    R --> O
    O -->|목표 근거 발견| D[완료 확인 후 반환]
    V -->|범위 밖 판단 필요| P
~~~

## 5. 작은 모델에 맞춘 질문

여러 검사를 합친 거대한 질문을 만들지 않는다. 현재 단계별로 가능한 선택지만 제공한다. 다음 입력 가능 여부는 코드 전이 조건이다.

| 단계 | SELECT 선택지 | 입력 허용 |
| --- | --- | --- |
| 입력 전 | 목표 근거 있음 / 후보 1–4 / 대기 / 자세히 보기 / 판단 요청 | 유효한 후보에 한함 |
| 드래그 후 | 목표 발견 / 내용 이동·목표 미발견 / 이동 중 / 변화 없음 / 다른 화면 / 판독 불충분 | 반복 조건을 만족할 때만 |
| 클릭 후 | 예상 결과 보임 / 전환 중 / 예상 결과 미확인 / 다른 화면 / 판독 불충분 | 기존 결과를 해소한 뒤 새 후보 선택 |
| 전송 여부 미상 | 결과 관측됨 / 더 기다림 / 판단 요청 | 새 입력 후보 자체를 제공하지 않음 |
| 완료 확인 | 대상과 종료 조건이 보임 / 아직 아님 / 판독 불충분 | 관측만 |

정상 드래그 반복은 효과와 목표를 위 선택지로 함께 판정한다. 새 클릭 대상을 고르거나 종료를 확정할 때는 추가 확인이 필요할 수 있다. 모든 동작이 SELECT 한 번으로 끝난다고 약속하지 않는다.

판독 불충분은 목표 없음과 다르다. 관련 영역 확대, 주변 문맥 포함, 이전/현재 비교로 문제를 좁힌다. 같은 이미지에 같은 질문을 그대로 반복하지 않는다. “이미 찾은 대상이 맞는가”처럼 긍정을 유도하지 않고 목표와 시각 근거를 제시한다. 같은 모델의 반복 확인이 독립적인 정확도 보증은 아니다.

후보 ID/라벨은 후보 수명 동안 유지한다. 잘린 JSON·잘못된 schema·누락된 logprobs·낮은 판정 신뢰도는 입력 허가가 아니다. 형식 수정도 기존 예산에 포함한다. legal mass/margin을 화면 판독의 정답 확률이라고 표현하지 않는다.

## 6. 클릭·드래그·대기

클릭은 정체성 확인 → 위치 탐색 → 현재 화면 유효성 확인 → 한 번 전송 → 예상 결과 확인까지 포함한다. 버튼이 계속 보인다는 이유만으로 재전송하지 않는다. 로딩이면 같은 ACT 안에서 기다린다.

드래그 후보는 표면 설명·포인터 이동 방향·예상 변화다. 부모에게 좌표나 격자 선택을 요구하지 않는다. 초기에는 locate의 확대·이동·확인으로 시작점을 찾고, 같은 표면의 도착점과 화살표로 표시한 경로를 확인한다. 판정은 “클릭 가능한 점인가”가 아닌 “이 표면에서 의도한 드래그가 가능한가”다. 잘못된 시작 힌트에서 전체 화면으로 돌아갈 수 있어야 한다.

목록은 이전 항목 일부가 남도록 길이를 선택한다. 지나쳤다는 근거가 있으면 짧게 되짚는다. drag-and-drop은 시작/도착 대상과 이동 결과를 확인하며 목록 탐색의 종료 조건을 강요하지 않는다.

자동반복 조건은 **직전 효과 관측 + 현재 목표 미발견 + 같은 표면·범위 유효**다. 판독되지 않은 조건이 있으면 관찰/복구한다. 표면의 기하 정보와 항목 정체성은 분리한다. 스크롤 후 경로는 재사용해도 같은 좌표의 항목 이름은 재사용할 수 없다.

WAIT는 내부에서 조건을 관찰한다. ACT 안에서는 허용된 개입 후보로 바뀔 수 있지만 독립 ny_wait는 입력 없이 개입 필요를 반환한다.

실제 예: 목표가 이미 보이면 드래그하지 않음 → 없으면 표면 탐색/드래그 → 결과 비교 → 이동했으면 반복, 무반응이면 보정, 발견하면 드래그 중지 → “찾기”는 증거 반환, “열기”는 위치 확인/클릭 → 상세 화면의 대상과 종료 조건 확인 → 부모 반환.

## 7. 갱신과 복구

현재 화면 확보와 재검증은 실행기 책임이다. 대상이 바뀌면 이미 확보한 새 이미지에서 내부 재탐색한다. 이미지 나이만으로 부모에게 ny_observe를 반복 요구하지 않는다. 반환 이미지를 사용하려고 반드시 다시 찍게 하지 않는다.

같은 이미지·행동·목표 revision의 유효한 판정은 재사용한다. 입력 직전 창/대상 변경을 확인한다. 픽셀 일치는 빠른 재사용 근거이며, 픽셀 변화 자체는 거절 근거가 아니다. 배경 애니메이션과 대상 교체·이동·가림을 구분한다. 움직이는 화면을 터치하는 동작에 완전 정지 조건을 강요하지 않는다.

복구는 범위 안에서 관측 가능한 원인에 대응한다. 무반응이면 표면/시작점·방향·길이, 전환 중이면 대기, 판독 부족이면 확대다. 바꾼 요소와 결과를 기억하고 같은 근거에서 같은 실패한 보정을 반복하지 않는다. 정해진 반복 횟수만으로 영구 차단하지 않는다.

무변화와 재방문은 목록 끝의 증거가 아니다. 범위 밖 메뉴 탐색은 부모 판단으로 반환한다. 드라이버·권한·누락 함수 오류를 좌표나 도구 변경으로 우회하지 않는다.

## 8. 입력 기록·재개·결과

입력 준비를 먼저 기록하고 전송/응답을 기록한다. 프로세스 중단이나 전송 타임아웃으로 응답이 없으면 unknown이다. 전송 여부를 항상 알 수 있다고 가정하지 않는다. 결과를 관측으로 해소하기 전 같은 입력을 자동 재전송하지 않는다. 드라이버가 명시적으로 전송 거절을 증명하는 기존 복구 경로만 구분해 유지한다.

continuation은 실행·목표 revision·절차 버전·단계·미확정 입력·탐색 영역·복구 이력·누적 예산을 보존한다. 새 목표/도구 호출도 미확정 입력과 마감을 지울 수 없다. 재개 시 창/화면은 확인한다. 같은 목표 문자열만 보고 임의의 과거 실행을 재개하지 않는다.

| 결과 필드 | 의미 |
| --- | --- |
| status | done / yielded / needs_decision / stopped / error |
| summary | 무엇을 했고 어디까지 확인했는지 |
| lastInput | 전송 not_sent/sent/unknown, 결과 observed/unresolved/not_applicable |
| evidence | 확인된 주장과 정확한 snapshot ID. 마지막 화면이 다르면 구분 |
| continuationId | 이어갈 상태가 있을 때 제공 |
| nextCall 또는 question | 같은 목표를 이어갈 호출 예시 또는 새로 필요한 구체적인 판단 |

done은 작은 목표만 완료한 것이다. yielded는 호출 예산 소진이며 실패/성공이 아니다. 마감 도달은 stopped이고 우회 재개를 제안하지 않는다. 새 사용자 입력·Escape·마감은 하위 루프보다 우선하며 이미 시작한 드래그의 버튼 해제를 보장한다.

내부 오류 코드만 반환하지 않는다. 예: “목록 이동은 확인했지만 두 항목의 이름을 확대해도 구별하지 못함.” 확인된 사실과 미해결 결정을 나눈다. 실제 개입이 필요하면 기존 ny_block으로 사유와 진행을 저장하고 종료한다.

부모가 출력 토큰 한도로 도구 호출 없이 끝나도 상태와 입력 기록을 보존하고 TUI에 이유를 표시한다. 같은 요청을 무한 재전송하거나 모델 설정/출력 한도를 몰래 바꾸지 않는다.

## 9. 기억과 학습

의미 있는 완료 경계의 진행과 근거는 실행기가 저장한다. 부모에게 매 클릭마다 플랜/체크포인트 호출을 요구하지 않는다. 추가 설명/교정은 기존 도구로 남긴다. 과거 기록과 현재 확인된 사실을 구분한다.

중간 확대/SELECT 이미지는 내부 분기에 보관한다. 현재/이전 관심 영역과 제한된 대표 화면을 기억하고, 부모에는 요약·마지막 이미지·필요한 완료 근거만 보낸다. 안정된 목표/후보 prefix를 재사용하되 실제 이미지 처리/캐시 비용은 provider에 따라 다름을 전제한다. 부모 대화의 기존 compaction 정책은 별개다.

저장 절차는 관련 앱/시나리오에서 소수만 가져온다. 이름 유사도만으로 실행하지 않고 현재 목표·범위·진입 화면을 확인한다. 맞지 않으면 즉석 후보를 쓴다. 절차 완료를 현재 목표 완료로 자동 간주하지 않는다. 자동 적합성 판단이 준비되기 전에는 명시적 flow 경로를 유지한다.

성공은 재사용 절차의 후보이며 한 번 성공을 범용 검증 완료로 승격하지 않는다. 모델이 적용 조건·종료 근거·실패/복구를 기존 지식/flow 도구로 저장한다. 기하 정보의 유효 범위를 보존하고 잘못된 지식은 교정한다. 게임별 지식과 모델이 만든 프리셋은 스킬 자료에만 저장한다. 제품 코드에 게임별 분기를 넣지 않는다.

## 10. 구현 구성

새 의존성·OCR·모델 서비스·공유 Cua/Hermes 변경 없이 기존 pi provider, SELECT, locate, 드라이버, 입력 잠금, 시간/중단, 지식 저장을 재사용한다.

1. src/execution-contract.ts: 계약·단계·결과·continuation 형식. 실행별 로컬 자료에 입력/재개 상태를 저장한다. 입력 전 기록에 실패하면 입력하지 않는다.
2. src/execution-controller.ts: 후보 공급, 단계별 SELECT, 입력 결과, 복구·반환의 공통 루프. src/action-runtime.ts는 위치/현재 화면 검증과 실제 입력 한 번에 집중한다. 입력 기록 책임은 중복시키지 않는다.
3. src/adaptive-act.ts는 즉석 후보, src/flow.ts는 저장 후보/전이를 공통 실행기에 공급한다. WAIT도 연결하되 후보와 디스패치 모두에서 입력을 금지한다. 세 벌의 결과/대기/정체 루프를 유지하지 않는다.
4. src/locate.ts에 드래그 표면·경로 판정을 연결하고 src/visual-memory.ts에서 기하와 정체성을 분리한다. 현재의 격자 셀 선택만으로 드래그를 확정하는 경로를 교체한다.
5. src/runner.ts와 extensions/nyatinorma.ts의 기존 진입점을 호환 어댑터로 연결한다. 필수 플랜, 매 입력 후 부모 검증, 반복 observe 유도 지침을 제거한다.
6. 제한적 절차 자동 재사용과 완료 경계 기록까지 확인한 다음 기본 도구를 축소한다. 실행 중 세션을 자동 재시작하거나 도구 의미를 조용히 바꾸지 않는다. 사용자 재시작/재로드 시 새 surface를 적용한다.

범위 밖: pi 포크, 모델/provider 설정 변경, TUI 전면 교체, 서버 캐시 구현, 게임 전용 플로, 대량 테스트. 구현 중 이 설계의 핵심 결정을 바꿔야 하면 임의로 더 복잡한 구조를 만들지 말고 차이를 기록한다.

## 11. 필요한 검증만

기존 테스트를 활용하고 다음 핵심 시나리오를 보강한다.

- 여러 번 이동해 찾고 여는 과정이 한 ACT 안에서 끝남. 처음부터 보이면 드래그 없음. 찾기만 요청하면 클릭 없음.
- 잘못된 표면의 무반응을 보정함. 정상 반복을 정체로 차단하지 않음. 장식 변화만으로 목록 이동을 인정하지 않음.
- 전송 미상·취소·마감 뒤 자동 재전송 없음. continuation이 탐색/복구와 누적 예산을 보존함. 기존 검사와 중복 테스트를 추가하지 않음.
- 대상 정체성과 종료 조건의 근거 없이 완료하지 않음. 판독 부족을 미발견으로 처리하지 않음. 현재 목표와 맞지 않는 저장 절차를 적용하지 않음.

부모 왕복, SELECT, 재탐색, 입력/진전/완료 근거를 기록한다. 위치 캐시가 유효한 정상 목록 반복은 보통 결과 SELECT 한 번으로 이어가는 것을 목표로 하되 필수 최신 화면 확인은 생략하지 않는다. 모의 테스트로 실제 모델의 장기 정확도/속도를 주장하지 않는다. 최종 보고는 변경, 핵심 검증, 남은 한계, 새 surface 적용 방법만 간결하게 한다.

## 12. 적용 범위와 한계

- 기본 작업 도구 일곱 개 외에 compaction 이력 조회용 읽기 전용 ny_recall이 유지된다.
- 목표·종료 조건·제약과 요청 revision을 보존한다. 별도의 LLM 계약 요약 단계는 넣지 않았으며 원 사용자 요청도 판단 문맥에 포함한다.
- 입력 전후와 완료 증거는 실행별 journal 및 trace에 저장한다. 성공을 스킬/flow로 승격하는 일은 기존 지식 도구로 모델이 수행한다.
- maxActions·maxSeconds는 호출별 실행 분량이다. resume은 누적 이력·카운터·시각 기억을 이어받고 새 호출 분량을 사용한다. 사용자가 지정한 run 마감은 재개해도 연장하지 않는다.
- 저장 절차는 목표 적합성 및 현재 진입 화면을 확인한 뒤 재사용한다. 절차 완료만으로 ACT의 원래 목표를 완료 처리하지 않는다.
- 모의 검증은 긴 드래그 반복, 단계 전환, 입력 전송 미상 후 재개 및 수동 중단 등을 다룬다. 실제 모델의 장기 자율 실행 정확도를 보증하지 않는다.

## 13. 화면 판단과 스크롤 복구

- 화면 재검증은 최신·이전 캡처의 Y/N SELECT가 최종 판단한다. YES 뒤 픽셀 오차로 다시 거부하지 않는다. 동일 픽셀은 호출 생략용이다. 클릭의 대상 정체성과 드래그의 컨테이너 연속성은 다른 질문으로 확인한다.
- 클릭 가능한 표면은 명시적인 tap-anywhere 화면도 포함한다. 닫기·제거 목표의 완료는 대상의 부재로 판정한다. 스크롤의 진전과 완료는 구분한다.
- 즉석 드래그 후보의 `surfaceRegion`은 전체 스크롤 표면을 4×4 격자 범위로 표현한다. 좁은 `regionPath` 위치 탐색 힌트와 구분한다. 진행 SELECT에는 전체 현재 장면과 확대된 이전·현재 표면, 제한된 과거 탐색 이미지를 제공한다. 부모 대화에 중간 이미지를 누적하지 않는다.
- SELECT는 계속·짧게·작게 반대로·재시도·발견·경계/순환·새 후보 필요를 고른다. 이동량과 방향 보정은 같은 실행 안에서 수행하고 재개 기록에도 보존한다. 픽셀 재방문은 비교할 과거 이미지를 고르는 힌트이며 입력 금지나 끝 판정이 아니다.
- 공통 SELECT의 후보 점수가 가까우면 확대 관측 후 상위 두 해석과 UNCLEAR로 한 번 더 선택한다. 확신 기준을 낮추거나 점수를 임의 합산해 입력을 승인하지 않는다.
- 전송 전 드래그 검증 오류는 `InputNotSentError`로 전달하여 입력을 not_sent로 정리한다. native 전송 뒤 실패에는 적용하지 않는다. 전송된 클릭의 예상 효과가 없으면 같은 원래 창에서 두 번의 최신 관측으로 확인하고 새 판단을 요구한다. 자동 반복하지 않으며 과거에 일시적인 효과도 없었다고 주장하지 않는다.
- 도구 그룹은 명시적인 ny 도구만 노출한다. 비활성화된 pi 내장 셸·파일 도구를 되살리지 않는다. 기록 전환은 미확정 입력을 우회하지 못하고 기존 마감을 보존한다. 해결된 차단 보고서는 저장하되 현재 차단 상태로 재주입하지 않는다.

## 14. 실화면 검증 범위

2026-09-28 수평 카드 목록 탐색에서 좌표 경계 검사 오류와 선택 점수의 모호함을 발견해 위 보완을 적용했다. 마지막 재개 호출은 약 3분 동안 드래그 9회(방향 보정 포함)와 클릭 1회를 부모 THINK 왕복 없이 수행했다. 작은 목표 카드를 발견·선택한 뒤 큰 메인 패널의 제목과 선택 표시를 실제 캡처로 확인했다. 이어서 해당 항목의 로비 진입도 확인했다.

이는 수정·재개 후 한 구간의 실검증이다. 최초 목록부터 무개입 성공, 전체 게임 작업 완료, 일반적인 성공률을 보증하지 않는다. 원본 캡처·사용자 지식·실행 이력과 복구 근거는 로컬 데이터에 보존하며 저장소에 포함하지 않는다.
