## Jev 방식의 정확한 범위

[Nokia AnyJev](https://github.com/nokia-applied-research/AnyJev)의 구분으로 현재 nyatinorma는 raw label-token 점수 선택에 가깝다. 선택지 내 정규화 점수는 실제 클릭 성공 확률이 아니다. AnyJev의 L0는 선택지 순서 편향 등을 줄이지만 K개 선택에 K번 prefill을 사용한다. L1은 라벨 데이터로 보정하며, L2는 질문·모델별 head와 중간 hidden state가 필요하다. 현재 프로젝트가 사용하는 Ollama chat API와 동등한 교체 부품으로 L2를 취급할 수 없다. AnyJev도 공개 평가가 독립된 결정 중심이며 실제 에이전트 루프 검증은 별도 과제로 명시한다.

당장은 현재 provider의 1토큰 logprobs 경로를 유지한다. 실제 선택과 관측 결과를 모아 선택지 순서 편향·오답·불필요한 기권을 먼저 평가한다. hidden-state 서버를 추가하거나 기존 Ollama 모델을 교체하는 작업은 이 개선에 포함하지 않는다.

## 적용 우선순위

1. **목표 이해와 좌표 변환을 분리한다.** 전체 화면으로 목표를 찾고, 필요할 때만 확대한다. 확대 좌표를 원본 좌표로 옮기는 계산은 런타임이 맡긴다. 격자는 선택 가능한 보조 수단으로 둔다. 고정 후보를 재사용할 때 A/B 표식을 붙이는 실험은 가능하지만, 잘못 잡은 후보를 표식이 정답으로 바꿔주지는 않는다.
2. **반복과 대기에서 THINK 왕복을 줄인다.** 모델이 관측된 상태·행동·종료 조건을 정의하고 런타임이 SELECT로 반복한다. 자동 진행 중에는 매번 설명을 생성하지 않고 WAIT/종료/예외만 고른다. 처음 정의하는 비용과 재사용 이득을 따로 측정한다.
3. **방문 기억과 처리 기억을 구분한다.** 현재 구현한 bounded scan memory는 과거 화면 재방문을 감지한다. 항목의 고유성, 이미 처리했는지, 남은 일이 무엇인지는 별도의 작업 상태가 필요하다. 끝 표시와 방문/처리 범위를 함께 확인해야 전체 탐색 완료를 주장할 수 있다.
4. **실패를 수정 가능한 지식으로 남긴다.** 오인식, 좌표 오류, 빠진 단계, 잘못된 완료 판정을 구분한다. 성공 증거와 실패 예시를 스킬에 남기고 버전을 관리한다. 모델의 자기평가만으로 검증된 성공으로 승격하지 않는다.

우선 실제로 실패했던 같은 화면·같은 목표에 직접 좌표, 격자, 확대 후 좌표, 후보 표식을 적용하는 작은 회귀 평가를 마련하는 것이 적절하다. 정확도뿐 아니라 총 추론 시간, 이미지 토큰, 호출 수, 추가 조작 수를 비교한다. 이 비교 평가와 표식 방식은 아직 구현하지 않았다. 연구를 참고한 설계와 이미 구현·실측한 기능을 구분해서 기록한다.
